# Support

Pick the channel that matches what you need. This keeps issues useful for maintainers and
searchable for everyone else.

| You need | Go here |
|---|---|
| Help deploying, configuring banks, or wiring up the SDK | [Discussions → Q&A](https://github.com/txsure/txsure/discussions/categories/q-a) |
| To propose a feature or discuss an idea | [Discussions → Ideas](https://github.com/txsure/txsure/discussions/categories/ideas) |
| To report a bug you can reproduce | [Open a bug report](https://github.com/txsure/txsure/issues/new?template=bug_report.yml) |
| To report a vulnerability | [Private security advisory](https://github.com/txsure/txsure/security/advisories/new) |
| To contribute code | [CONTRIBUTING.md](https://github.com/txsure/txsure/blob/main/CONTRIBUTING.md) |
| To self-host production | [docs/self-hosting.md](https://github.com/txsure/txsure/blob/main/docs/self-hosting.md) |

## Before you ask

1. Read the README section for the thing you are doing. Most setup questions are answered
   there or in `docs/self-hosting.md`.
2. Search closed issues and discussions — someone has probably hit it already.
3. If you are debugging, include your txsure version, deployment shape (Docker or
   `pnpm dev`), and the relevant API logs.

## Support scope

txsure is maintained by volunteers and is provided under the MIT license, without a
warranty or a service-level agreement. We help as time allows and we prioritise security
reports, reproducible bugs, and contributions over general consulting.

If you need a guaranteed response for a production deployment, plan for in-house
ownership of the stack — that is the trade-off of self-hosting.
